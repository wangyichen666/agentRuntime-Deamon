# 第四轮：历史原文锚点的覆盖状态

研究日期：2026-10-05。仍以Codex固定提交 `8d44977aa2fb9ae1b128660668dc5b36966613fa` 为参考。

## 研究结论

Codex `context_manager/history_user_authorization.rs` 明确区分 Original/Checkpoint，超大原文与legacy材料标 `complete=false`；checkpoint即使短也不证明原始完整性。当前项目历史用户锚点仅保存字符串数组：超过独立预算时丢弃旧项，但不记录已知丢失；旧摘要没有锚点时，重压缩更不能判断哪些约束已消失。这是可由宿主验证的结构缺口，先补覆盖记录比直接宣称模型摘要更准确可靠。

## 开发前计划

1. 锚点JSON升级为v2对象，保存inputs、text_complete与omitted（已知省略数量下限），兼容读回v1数组。该完整性只针对历史非空、去重后的用户文字，不代表图片、对话完整性或用户授权。
2. 任何checkpoint/legacy摘要只能作为不完整历史来源，不能因下一次预算充裕恢复complete=true；v2继续携带既有省略下限，新的省略使用饱和加法。未知摘要标为不完整，不猜测缺失内容。
3. 包装和所有覆盖字段计入锚点独立预算；能装下小输入时不被大输入挡住。即使锚点预算为0，宿主checkpoint仍保存覆盖字段并说明省略，后续压缩可继承。
4. 独立JSON评测覆盖完整原文、零预算、较大项跳过、旧数组恢复、未知旧摘要、不完整状态延续；模型摘要包装也核实字段。运行保护仍以持久层当前轮次原文suffix为准。

这是结构性的丢失诊断，不能推算语义约束覆盖率，也不能证明摘要或模型回答质量提高。真实收益需要原始约束与回答事实的人工标签、成本数据和对照评测，继续纳入数据飞轮待办。

## 实施与验证结果（2026-10-05）

v2锚点、旧数组兼容、已知省略下限、checkpoint不完整状态和零预算摘要诊断均已接线。6项独立保留样本与原15项当前轮次保护样本共同形成21项上下文结构门禁；预算0至179的Unicode/元数据边界验证全部包装计量，真实压缩候选测试验证零预算省略诊断继续传递且当前轮次原文保留。完整Rust289项、Web27项、debug/release检索17/17与上下文21/21，Clippy、MSRV1.88、release、fmt/diff和离线cargo-deny通过。

后续优先研究：请求压缩前如何预留交接/记忆材料预算；将真实摘要约束丢失与用户纠错归入可复现评测；语义提炼/矛盾整合是否有优于当前确定性策略的证据。上述语义收益尚未证明，不自动以模型生成标签替代用户反馈。
