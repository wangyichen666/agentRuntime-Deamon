## 动手前确认清单的回答

1. **13 库与边**：实际生产依赖在 [baseline-index.md](baseline-index.md)，机器可读职责与边在 [crate-boundaries.toml](crate-boundaries.toml)。根组合可依赖 daemon/runtime，入口不能。runtime 当前仍依赖 storage crate 提供的 ports，也依赖 daemon-protocol 共用事件，这是实际基线，不虚构已完成未来 ports 独立拆分。
2. **v20 全表 / 事务 / 迁移**：见 [schema-v20.md](schema-v20.md)。`RunStore::lock_connection` 串行共享 Connection；mutation transaction 经 `views::commit` 封存 snapshot/stamp 后 commit，随后广播。`open` 检查 MAX migration >20 拒绝，v1–19 升级前 VACUUM 备份/integrity/版本/SHA marker。运行时有 WAL/busy_timeout；不是跨实例 writer lease。
3. **四类身份**：ExactOwner 的五维在事务 `fence_in` + SQL triggers 复核；SessionLifetime 防同 key 重建；RunGeneration 不 wrap；ProjectionGeneration + source revision/digest CAS 防旧 compact/请求读回。它们不提供主体授权、tenant 隔离或分布式 lease。
4. **状态机与 terminal owner**：runs/turns/queue/interactions/plans/compact/delegations/resources 均落在同一 SQLite；daemon 是编排/句柄 owner，broker/active map 不是终态。重启 active 执行 unknown、resource orphaned、approval orphaned、queued 保留；不重放外部副作用。计划是用户执行计划，不能用其表作为独立工作流 DAG。
5. **入口共享**：CLI/TUI/ACP/gateway → daemon-client → daemon-protocol/core；root Host 组合。transport EOF/timeout、popup Cancelled、展示 reducer/resync 不提交 run/interaction 终态；终态需要 repository 事务证据。
6. **无界队列**：四个生产构造站点和一个 fixture 站点，详见 [channel-budget.md](channel-budget.md)。不能用前端队列预算声称服务端 WS 已有界。Wave 0 冻结精确书面例外，Enterprise 网络上线前必须收口。
7. **准入冻结**：RunSnapshot 当前含 route/tools/cwd/permission mode/requested+effective sandbox/docker_image/config generation/context read-only+fingerprint+budget/catalog digest/memory budget/max tool calls/entry channel/delegation context；每次发送另存 capture。**无 authenticated principal/role set/PolicyVersion/tenant/project/agent UID**。不是所有动态 Skill/MCP 状态都作为 Agent 产品 generation 冻结。
8. **MCP/Cron/Hook/Skill/子 Agent**：上表逐项真实接线；外部 commercial Provider/用户 hook/真实 IDE/MCP/Keychain/Linux/CI 与生产负载尚未验证。Cron JSON 是需要迁移的管理事实，迁移必须复用 scheduler，不建第二个 cron owner。
9. **安全保证**：safe rustix fd、no-follow、hardlink/身份/content CAS、原子 rename 是文件工具真实保证；Native 对同 UID shell 仍为软边界。Docker 前台严格拒绝 fallback；后台资源当前只支持 Native。不能将 preflight/mock 说成真实容器隔离 oracle。
10. **Local 兼容冻结**：binary `my-agent`、CLI/TUI/slash、默认 ACP v1/显式 v2、现有 env/config、workspace/socket/startup markers、HTTP/SSE/WS、schema v20 向前升级、JSONL 一次导入/证据、cancel/unknown/no replay/readback/reducer 合同。企业字段必须保持 legacy 解码语义，Local 不依赖 PG/OIDC/K8s。
11. **tenant query 目标**：现在无 tenant 列，不能假设已有隔离。Wave 1/2 所有入口 context 来自服务端认证；repository SQL 必须带 tenant/project/agent 域，组合唯一键和 FK，不能 global lookup 后内存过滤；旧数据明确落保留 local 域，不能在线模糊推断。
12. **PG 同合同目标**：先领域 ports/transaction command 梳理，复用 admission/commit/fence/error 合同，文件/内存 SQLite 测试保留；增加真实 PG lane。不得把 sqlx mock 或 SQLite 内存合同冒充 PG 验收。
13. **管理/使用面目标**：独立路由/端口/audience/scope/主体能力；二者同 canonical policy/storage/audit ports；Gateway projection-only。当前仅使用面，没有管理 API，设计见 ADR 0004–0009。

## Wave 0 范围与实施计划

范围：根 ARCHITECTURE、6 份 ADR、能力/全表/需求矩阵，扩展现有 AST/Cargo 护栏和恶意夹具、复跑完整门禁。修改 tests/architecture_contract.rs、文档和规划文件；不新增 production crate、不新增 schema（仍 v20）、不改实际业务状态机。

RED 顺序：实际旧 checker 对 qualified placeholders 失败（已记录 exit 101）→ 修复；manifest alias/target/build/inherit、shadow owner、unbounded alias/std/zero-capacity fixtures 必須返回违规；覆盖所有 workspace 新库（未审核库 fail closed）。GREEN 后跑全 workspace/Clippy/MSRV/release/Web/deny。
